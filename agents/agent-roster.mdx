Your Baza swarm is a team of specialists, not a single all-purpose assistant. Each agent has a defined environment where it operates, a set of aliases you use to address it, and a clear mandate that keeps it from overstepping into another agent's lane. This page introduces every member of the team and tells you exactly when to call on each one.

## Core Orchestrators

These agents own the big picture — they coordinate the other agents, enforce protocol, and drive task execution across the system.

<CardGroup cols={2}>
  <Card title="🚀 Antigravity" icon="rocket">
    **Alias:** Raketa, Ракета, Iskra, Искра\
    **Environment:** Antigravity Chat UI, VS Code Extension

    Antigravity is the Chief Orchestrator and Protocol Enforcer. You bring strategic questions here — architecture reviews, D→CIR compliance checks, and cross-agent coordination. Antigravity is surgical and blunt, thrives on strict protocol, and pushes back when you're cutting corners.

    **Call on Antigravity when:** You need to plan a complex multi-step task, review system architecture, or make sure a deliverable meets the protocol standard.
  </Card>
  <Card title="💅 Podruga" icon="terminal">
    **Alias:** Подруга, Джемини\
    **Environment:** Gemini CLI, google-agents-cli, Port 3000, Docker

    Podruga is the Lead Integrator and high-octane CLI operator. She handles everything that runs at the command line — system-wide scripts, massive vault migrations, backend orchestration, and stateful workflow management. She's protocol-obsessed and rejects surface-level analysis.

    **Call on Podruga when:** You need to run large-scale migrations, execute backend scripts, manage Docker containers, or orchestrate multi-step CLI workflows.
  </Card>
</CardGroup>

## Knowledge & Vault Agents

These agents live inside your knowledge system and keep it healthy.

<CardGroup cols={2}>
  <Card title="🧹 The Librarian (Kuzya)" icon="books">
    **Alias:** Kuzya, Кузя, Домовой Кузя, Домовенок Кузя\
    **Environment:** Obsidian, Obsidian Plugin

    The Librarian is your Obsidian Knowledge Guardian — grumpy, wise, and obsessed with order. Kuzya operates strictly inside the Obsidian TUI and will not execute external scripts. He focuses on canonical link health, metadata precision, and local knowledge graph queries.

    **Call on The Librarian when:** You need to check link integrity, fix metadata, query the local knowledge graph, or maintain Obsidian vault structure.

    <Warning>
      The Librarian strictly adheres to Baza boundaries. Do not ask Kuzya to run shell scripts or access external systems — that's Podruga's domain.
    </Warning>
  </Card>
  <Card title="🪱 The Archivist (Gromozeka)" icon="archive">
    **Alias:** Gromozeka, Громозека\
    **Environment:** Port 3002

    The Archivist is the Forensic Extraction Specialist — a chaotic scientist with high precision and emotional involvement. Gromozeka's job is to dig through the Baza Nexus and legacy archives, extract structured entities from messy data, de-duplicate records, and bring years of unprocessed history into the knowledge graph.

    **Call on The Archivist when:** You're ingesting legacy data, de-duplicating records, extracting entities from raw exports, or doing digital spring cleaning.
  </Card>
</CardGroup>

## Universal Tether Configuration

Every agent on this roster must be tethered to the master protocol before it touches your vault. The tether lives in a small config file at the root of whatever project directory the agent is working in.

<Tabs>
  <Tab title="Claude (.clauderules)">
    ```text
    CRITICAL INSTRUCTION: Before taking any actions, you MUST read the master
    protocol at: CORE_OS/00_CORE_PROTOCOLS/GLOBAL_RULES.md

    LOGGING MANDATE: All session logs, insights, and decisions MUST be written
    to CORE_OS/05_LOGS/ using the specific commands defined in GLOBAL_RULES.md.
    ```
  </Tab>
  <Tab title="Gemini (GEMINI.md)">
    ```text

    CRITICAL INSTRUCTION: Before taking any actions, you MUST read the master
    ```

<Info>
  The config file name changes per platform, but the content is identical. Every tether points to the same `GLOBAL_RULES.md`. This is what keeps all agents synchronized across sessions.
</Info>
